# v0.4 — `app-builder`: NLP → train/export/package/POC

**Date:** 2026-05-06
**Status:** Approved (brainstorm)
**Predecessors:** v0.1 scaffold, v0.2 remote, v0.3 naming + experiment log.

## Goal

Turn an NLP request like *"build a cat detect app for me on nvidia chip from this
video"* into a deployable ModelBox project plus a POC video, by composing the
plugin's primitives. The plugin only exposes good primitives; the orchestration
lives in a skill Claude reads.

## Audience and constraints

- Hardware target for v0.4: **NVIDIA only** (TensorRT engine, ModelBox `cuda`
  runtime image). Ascend / Intel Arc / Apple come later.
- Service shape for v0.4: **file-shape only** — input is a video file, output
  is an annotated video file plus rich metrics. RTSP/HTTP later.
- Detection class scope for v0.4: **COCO80 shortcut only** — if the requested
  class is in COCO80, use `yolo11n.pt` and filter classes at postprocess. If
  the class is not in COCO80, the orchestrator stops and tells the user
  "fine-tune flow lands in v0.5". (Confirmed acceptable.)
- Execution host: **pose** (RTX 5090, Linux). The plugin's existing remote
  config (v0.2) handles the SSH wrapping. Pose needs a one-time install
  (docker + a built ModelBox cuda-runtime image).

## Components added in v0.4

### Two new commands

- **`/ultralytics:package`** — Stamp a deployable wrapper around an exported
  artifact. v0.4 supports `target=nv shape=file`. Produces a directory
  containing a ModelBox project, a Dockerfile, a `manifest.json`, and a `Makefile`
  with `build`, `run`, `clean` targets.
- **`/ultralytics:poc`** — Run a packaged app against a user-provided video.
  Streams the video through the docker-built ModelBox image, captures
  annotated output and rich metrics, appends to the experiment log.

### One new skill

- **`app-builder`** (`skills/app-builder/SKILL.md`) — The NLP entry point. Fires
  on phrases like "build me a … detector / app / POC … on nv|nvidia|jetson".
  Encodes the decision tree below; calls existing slash commands in order.

## Decision tree (encoded in `app-builder` skill)

```
1. Parse user intent → {classes: [str], chip: str, poc_input: path?, name: str?}
2. Resolve classes:
   - Each class ∈ COCO80? → SHORTCUT: model = yolo11n.pt; class_filter = [ids]
   - Any class ∉ COCO80? → STOP, message "v0.4 supports COCO classes only;
                            fine-tune flow lands in v0.5"
3. Resolve chip: v0.4 only allows nv/nvidia/jetson → target=nv. Others stop.
4. Confirm host: read .ultralytics.yml. If no remote, prompt user to set
   remote=pose (or another nvidia host). Pose smoke-test:
   - command -v docker (must exist)
   - docker images | grep modelbox-cuda-runtime (must exist; if not,
     guide one-time install per README)
5. /ultralytics:export model=yolo11n.pt format=engine device=0
   (runs ON pose; engines are GPU-arch-specific). Produces yolo11n.engine.
6. /ultralytics:package target=nv shape=file engine=<path> classes=<ids>
   names=<labels> name=<from app-builder or auto>
   → produces ./packages/<name>/ on local fs (the package is portable).
7. If poc_input was provided:
   /ultralytics:poc package=./packages/<name> video=<poc_input>
   → produces ./packages/<name>/poc/<video-stem>/ with:
       - annotated.mp4
       - detections.jsonl  (per-frame)
       - metrics.json      (latency, fps, per-class counts)
       - report.md         (human-readable summary)
8. Append summary row to runs/EXPERIMENTS.md (existing v0.3 log).
```

## ModelBox project template (target=nv shape=file)

Generated directory structure (under `./packages/<name>/`):

```
<name>/
├── Dockerfile                    # FROM modelbox-cuda-runtime; copies project in
├── Makefile                      # build, run, clean
├── manifest.json                 # provenance (see below)
├── README.md                     # how to build/run/POC the package
├── model/
│   └── yolo11n.engine            # the exported TensorRT engine
└── modelbox/
    ├── desc.toml                 # project descriptor
    ├── graph/
    │   └── <name>.toml           # the pipeline graph
    └── flowunit/
        ├── infer/                # uses common 'inference' flowunit
        │   └── infer.toml        # entry=../../model/yolo11n.engine, virtual_type=tensorrt, device=cuda
        ├── preprocess/           # python flowunit: letterbox to 640, normalize, BCHW
        │   └── preprocess.toml
        │   └── preprocess.py
        ├── postprocess/          # uses ModelBox's yolo26_post (or yolo postprocess) flowunit, configured for our class set
        │   └── postprocess.toml
        └── draw_filter/          # python flowunit: filter detections to class_filter, then format for draw_bbox
            └── draw_filter.toml
            └── draw_filter.py
```

The graph wires:

```
file_source → video_demuxer → video_decoder(cuda) → preprocess(cuda) →
  infer(cuda, tensorrt) → postprocess(cpu) → draw_filter(cpu) →
  draw_bbox(cpu) → video_encoder(cpu) → file_sink
```

Plus a **JSON event sink** branch off `draw_filter` that writes `detections.jsonl`.

All flowunit names are taken from `src/drivers/common/flowunit/` and
`src/drivers/devices/{cpu,cuda}/flowunit/` of the upstream ModelBox repo.

`Makefile` exposes:

- `make build`  — `docker build -t <name>:latest .`
- `make run VIDEO=path/to/in.mp4 OUT=./poc/in/`  — `docker run --gpus all -v $VIDEO:/in.mp4 -v $OUT:/out <name>:latest`
- `make clean` — removes built image and `./poc/`

## `manifest.json` schema

Frozen alongside the package for traceability:

```json
{
  "package_name": "20260506-1432_yolo11n_coco8_e10_b8_a1b2c3d_cat",
  "package_version": "0.1.0",
  "created_at": "2026-05-06T14:32:00Z",
  "source_run": "20260506-1432_yolo11n_coco8_e10_b8_a1b2c3d",
  "ultralytics_version": "8.x.y",
  "modelbox_base_image": "modelbox-cuda-runtime:ubuntu",
  "model": {
    "engine_path": "model/yolo11n.engine",
    "sha256": "…",
    "exported_from": "yolo11n.pt",
    "format": "engine",
    "imgsz": 640,
    "gpu_arch": "sm_120"
  },
  "classes": {
    "all_names": ["person", "bicycle", "…", "toothbrush"],
    "filter_ids": [15],
    "filter_names": ["cat"]
  },
  "service_shape": "file",
  "target_chip": "nv"
}
```

The orchestrator computes `package_name` by suffixing the source run name with
the requested label (e.g. `_cat`).

## POC output (rich)

`/ultralytics:poc` produces these files inside `./packages/<name>/poc/<video-stem>/`:

- **`annotated.mp4`** — original video re-encoded with bounding boxes drawn
  per frame. Boxes show only filtered classes.
- **`detections.jsonl`** — one line per frame:
  ```json
  {"frame": 0, "ts_s": 0.000, "detections": [{"cls": "cat", "conf": 0.91, "xyxy": [120, 88, 412, 320]}]}
  ```
- **`metrics.json`** — aggregate metrics:
  ```json
  {
    "frames_total": 1500, "duration_s": 50.0,
    "fps_avg": 142.3, "fps_p50": 145.0, "fps_p99": 88.1,
    "latency_ms": {"avg": 7.0, "p50": 6.9, "p99": 11.4},
    "per_class": {"cat": {"frames_with_detection": 1342, "max_per_frame": 3, "conf_p50": 0.86, "conf_p99": 0.95}}
  }
  ```
- **`report.md`** — human-readable summary: "Detected `cat` in 1342/1500 frames
  (89%); avg 142 fps on RTX 5090; output saved to annotated.mp4". Two charts
  (matplotlib SVG inline) for fps over time and per-class confidence
  distribution. (Charts are nice-to-have; v0.4 ships text-only if charts add
  scope.)

`metrics.json` is parsed from a sidecar JSON-event flowunit run alongside the
draw branch. `latency_ms` is measured by ModelBox's profiler (already supported
in graph `[profile]` block).

## Preflight: one-time setup on the GPU host

Documented in README + reinforced by the `app-builder` skill on first run:

```bash
# 1. Docker (with NVIDIA runtime)
ssh pose 'curl -fsSL https://get.docker.com | sh && \
          sudo apt-get install -y nvidia-container-toolkit && \
          sudo nvidia-ctk runtime configure --runtime=docker && \
          sudo systemctl restart docker'

# 2. Build ModelBox CUDA runtime image (one-time, ~15 min)
ssh pose 'git clone https://github.com/modelbox-ai/modelbox.git ~/modelbox && \
          cd ~/modelbox && \
          docker build -f docker/Dockerfile.cuda.runtime.ubuntu \
                       -t modelbox-cuda-runtime:ubuntu .'
```

The plugin's preflight checks for `docker` and the `modelbox-cuda-runtime:ubuntu`
image; if missing, it shows the commands above and stops without further action.

## Smoke test plan (manual, one-shot)

On the host machine, in any cwd with `.ultralytics.yml` pointing at pose:

1. **Direct primitive test** (no NLP):
   ```
   /ultralytics:export model=yolo11n.pt format=engine device=0
   /ultralytics:package target=nv shape=file engine=runs/detect/<run>/weights/yolo11n.engine \
                        classes=15 names=cat
   /ultralytics:poc package=./packages/<name> video=./samples/cat.mp4
   ```
   Expect: `./packages/<name>/poc/cat/annotated.mp4` exists with boxes; metrics.json
   shows `frames_with_detection > 0` for `cat`; report.md lists the summary.

2. **NLP test** (the magic):
   ```
   "build a cat detect app for me on nvidia chip and POC on ./samples/cat.mp4"
   ```
   Expect: `app-builder` resolves cat→class 15 (COCO80), runs the three primitive
   steps, returns the same artifacts as above.

3. **NLP test, miss path:**
   ```
   "build a giraffe-and-traffic-cone detector on nv"
   ```
   `traffic cone` is not in COCO80. Expect: `app-builder` stops, message
   "v0.4 supports COCO80 classes only; traffic cone needs custom training (v0.5)".

## Out of scope (v0.4)

- Custom training (class ∉ COCO80). v0.5.
- Ascend / Intel Arc / Apple targets. v0.6+.
- HTTP / RTSP / live-camera shapes. v0.6+.
- ModelBox install automation (one-time setup is documented, not automated).
- Production-grade ops (CI, monitoring, autoscale, drift detection).
- Charting in `report.md` if it adds scope; text summary is the v0.4 floor.

## Open risks (acknowledged, not blockers)

- **TensorRT engine portability.** The engine built on RTX 5090 (sm_120) won't
  run on Ampere/Hopper/Jetson. The package's `manifest.json` records `gpu_arch`
  so a mismatch is detectable at deploy time. Cross-arch deployment requires
  rebuilding the engine on the target — out of scope for v0.4 but cheap to
  surface as a postflight warning in `/ultralytics:poc`.
- **ModelBox flowunit names.** The spec assumes flowunit names from upstream's
  `master`. Pin to a specific ModelBox commit in the Dockerfile to avoid drift.
- **Python flowunits inside the package.** The preprocess and draw_filter flowunits
  are Python (using ModelBox's `python` flowunit type). Verified upstream
  supports this; risk only if pose's runtime image lacks the right cv2/numpy.
  Dockerfile pins versions.
